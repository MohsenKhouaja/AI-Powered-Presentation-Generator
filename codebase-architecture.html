Strong ports & adapters 01

Make Slide persistence one deep module

Files

backend/api/slides/slides-service.ts backend/api/presentations/presentations-service.ts backend/database/index.ts
ProblemMySQL metadata and Mongo content leak across the Slide seam, so create, delete, generation, and detail reads each invent cross-adapter failure behavior.
SolutionDeepen the Slide module until all assembly, ordering, replacement, compensation, and reconciliation live in its implementation.

Before · storage knowledge leaks

flowchart TB
  PR[Presentation module] --> SQL[(MySQL)]
  PR --> M[(MongoDB)]
  SR[Slide module] --> SQL
  SR --> M
  GEN[Generation] --> SR
  GEN --> SQL
  classDef leak fill:#fef2f2,stroke:#dc2626,stroke-width:2px;
  class PR,SR,GEN leak;

After · one seam owns consistency

flowchart TB
  C[Presentation + generation callers] --> D[Deep Slide module]
  D --> META[Metadata adapter]
  D --> CONTENT[Content adapter]
  META --> SQL[(MySQL)]
  CONTENT --> M[(MongoDB)]
  classDef deep fill:#172033,color:#fff,stroke:#172033,stroke-width:4px;
  class D deep;

Benefits

  • Locality: one failure policy
  • Leverage: every Slide caller
  • Tests hit one interface
  • Adapters stay internal
Deletion test: deleting the current Slide module spreads real complexity, but Presentation already bypasses its seam. Deepen the module; do not add another shallow module.

Stronglocal-substitutable04

Own the Context attachment lifecycle

Files

backend/api/contexts/router.tsbackend/api/contexts/contexts-service.tsbackend/api/files/files-service.tsbackend/config/uploads.ts
ProblemUpload writes, SQL metadata, filesystem cleanup, base64 reads, and rollback ordering are split across three modules.
SolutionAbsorb the shallow File module and make Context own staging, scoped attachment changes, cleanup, and read representations.

Before · commit order escapes the seam

sequenceDiagram
  participant R as Context route
  participant F as Filesystem
  participant C as Context module
  participant S as SQL
  R->>F: Multer writes
  R->>C: create/update
  C->>S: metadata transaction
  Note over F,S: Later failure leaves one side changed
  C->>F: delete after SQL row

After · lifecycle stays behind one seam

sequenceDiagram
  participant R as Context route
  participant C as Deep Context module
  participant S as SQL adapter
  participant F as Filesystem adapter
  R->>C: attachment change
  C->>F: stage
  C->>S: persist scoped metadata
  C->>F: commit or compensate
  C-->>R: complete Context result

Benefits

  • Locality: one attachment policy
  • Leverage: create and update
  • Temp-dir tests hit interface
  • Cleanup becomes verifiable
Deletion test: deleting createMany moves one SQL statement into Context. The File module is shallow; Context should absorb its implementation.

Worth exploringin-process06

Deepen authentication and session lifecycle

Files

backend/middleware/auth.tsbackend/routes/auth.tsbackend/api/{presentations,slides,presentations_access}/router.tsfrontend/src/context/AuthProvider.tsxfrontend/src/hooks/{useApiClient,queries/useAuthSession}.ts*
ProblemToken signing, verification, request identity, refresh, retry, request normalization, and session state are duplicated or exposed through shallow modules.
SolutionDeepen the existing authentication modules on each side of the HTTP seam; protected callers consume established identity and session state.

Before · thin bands repeat knowledge

After · two deep modules, one HTTP seam

Deep frontend session modulestate · refresh · retry · normalization
HTTP seam

Benefits

  • Locality: token lifecycle
  • Leverage: every protected call
  • Identity tests avoid JWT setup
  • Session tests cover retry
Deletion test: router token helpers and session query modules mostly vanish when deleted; the provider and middleware contain the depth worth preserving and increasing.

Top recommendation

Make Slide persistence one deep module

It has the highest leverage and the most immediate integrity risk: today a single Slide workflow can leave MySQL and MongoDB disagreeing, while Presentation callers bypass the existing seam.
